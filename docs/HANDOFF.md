## 入口与模块所有权

| 文件 | 内容／修改方式 |
| --- | --- |
| `tts/Global.lua` | 直接复制进 TTS 的完整 Global。分隔符之前是部队源代码；之后是同步生成的面板与地图旗。不要把整个文件视为可全部重新生成的空壳。 |
| `tts/modules/commanders.lua` | 独立武将面板源；包含 `PANEL_XML`、Description 解析、四備十二名初始人物、座位视图、状态／命令写回，以及独立事件包装。 |
| `tts/modules/map_flags.lua` | 地图旗源；通过标记区嵌入面板和 Global，不能单独当成整个 Global 运行。 |
| `tts/releases/Global_v2.16.0.txt` | 当前全量安装版本，与 Global 字节一致；v2.14.11、v2.15.0 保留为旧发布快照。 |
| `tools/tts/sync_global.py` | 保留 Global 的部队前缀，把地图旗注入面板，再把面板注入 Global；`--check` 不写文件。 |
| `tools/tts/test.ps1`、`tests/tts/behavior.lua` | 本机 TTS MoonSharp + 模拟 API 行为检查、实际生成 XML 的结构／回调检查。 |

| `docs/tbs/history/`、`tts/archive/` | 旧版原文和源码，用于追溯，禁止直接当作最新版安装。 |

## 已实现的状态和流程

### 部队

- `UNIT_CONFIGS`：十种 Tags 驱动的配置，见 CONFIGURATION.md；`COUNT_CONFIGS` 为 100～400 人，显示 1～4，默认 1。
- `unit_state[GUID]` 保存 `front_value`、`back_value`、`acted`、`manual_defeat_visible`、`config_tag`、`engaged`、`out_of_command`、`open_order`、`reloading`。`onSave()` 只序列化 `{unit_state=...}`；`onLoad()` 容错恢复、注册快捷键、预载图片、安排扫描并初始化面板。
- 两项新字段为严格布尔值，旧存档缺失／无效值默认为false。所有玩家左键切换，右键忽略；正反面共用，允许同时启用。移动／翻面／敗走／士气恢复都保留手动标记；仅再次点击或显式 `resetUnit()` 清除，不自动执行接敌、指挥距离或行动限制。
- 底部 `open_order`、`reloading` 为严格布尔值，默认false（密集／准备完成）；由 `UNIT_CONFIGS.marker_mode` 显式选择适用组。所有玩家左键切换、右键忽略；不改士气、行动、翻面或顶栏状态；完整reset清除，快捷补满保留。不自动执行换阵成本、射击限制或回合恢复。
- 新 GUID 首次从两面上限开始；已有棋子保留状态并按新上限截断，不因换标签自动治愈。销毁时清理对应缓存和状态。
- 左键士气 +1、右键 -1；绑定的「士気快捷調整」按住后，左键补满并解除敗走、右键清空。按键状态按玩家分离，加载／换座／离线时清除，不持久化。
- 正面从正数降至 0 自动翻背并补满背面；背面 0 或手动敗走标志触发敗走显示。翻面有 0.5 秒连点保护。普通回升背面士气、快捷补满与手动标记的细节以 `changeUnitMorale()` / `getDefeatText()` 为准。
- `acted` 独立于正反面，点击右上行动格切换；清空／补满士气不擅自重置行动。没有全局“下一回合”自动清除所有行动。
- 士气未满且大于半数显示琥珀色带，半数及以下显示红色带；满值、零值／敗走不显示损耗带。正面黑数字，背面象牙白数字。
- 没有数字／行动图时不再回退文字，透明点击区域保留。旧四个 name/number color 字段已删。敗走缺图文字回退与武将画像提示仍在。
- `UNIT_DEFEAT_IMAGE_URL` 仍是现有方形贴图：中心约 `(450,720)`、宽480；新的大图标／悬浮横牌没有实现。

### 武将、備隊与存档

- Description 使用逐行 `key=value`，`team` + `role` 定位成员；有效字段优先于内置人物默认值。主将一个，两位副将左右并列。同隊同角色重複会阻止相应操作。
- 所有玩家可切换「無傷／浅手／深手／討死」和備隊命令。状态、命令写回令牌 Description，随 TTS 场景保存；原始 `command` 不因伤势被覆写。
- 無傷机动9；浅手／深手机动4；浅手不减统率，深手减1最低0；討死统率X、机动—。六格统率条用单格X取代失效圆点。
- 討死画像为灰色乘色压暗，**并不是真正的黑白灰度转换**。不能对用户声称已实现真灰度。
- 武将行动由令牌翻面表示，和普通部队独立 `acted` 不同。统一済印在背面与画像显示。
- 十二座位各有面板、固定／缩放／关闭状态；Grey 共用一个视图。状态写回共享物件，面板查看互相独立。面板视图不持久化。
- `formation` / `order` 是名称和显示信息；攻撃、防御、機動、再編按钮没有自动实施战斗／移动规则。

### 阵旗与渲染

- 主将 `flag_image` 提供本備旗。普通部队通过所属 Tags 关联；旗以双面贴花常显，所有人都可见。普通部队不再依赖旧版各玩家展开旗模式。
- 武将等非部队物件仍保留地图旗模块中的悬停／展开行为。面板的「本隊陣旗」与历史文档描述不能混同于部队常显贴花。
- 部队正面：数字／行动／色带贴花。背面：一个 Object.UI 组合底栏、数字、行动、色带。经典透明按钮负责点击。
- 新状态图标在同一 Object.UI 管理器内新增两个顶栏Panel，正面旋转 `0 0 180`，背面 `180 0 0`；每项只登记一张图片，用透明度区分开关。原背面右栏及其六个子节点保持独立；图标全部 `raycastTarget=false`，透明经典按钮只在资源／XML就绪后建立。
- 底部两面根节点 `sgub_mode_front/back` 各含一个Image，中心X850/Y1130、显示240×110、点击260×130。每枚只预载适用两图，普通点击只更新image属性，不重建XML或增添Canvas，不新增每帧扫描；缺图整组隐藏，换兵种时切组并保留另一组手动记录。
- UI 资源需先 `setCustomAssets()`，等加载后再 `setXmlTable()`；不能退回曾出白块的第二参数资源传法。冷启动时 `loading=false` 也不保证节点可读，现实现用 XML 查找、异常保护和重试。
- 清理仅限自有 `sgub_`、`sgmf_` 等节点／资源及自有贴花，避免删除物件的其他脚本 UI。
- 实测位置必须保留：部队 front gap `-0.01`、back gap `-0.099`、背面 UI clearance `-0.099`；武将 `BACK_STAMP_GAP=-0.099`。不能把背面重新改为底栏和数字层层叠贴花来“修复”。

## 规则、设定与美术

- 当前项目参考 RAN，但全兵种统一两阶段士气是已采用的改编机制；RAN 的远程背面和敗走离场规则不同，见 [规则对照](tbs/RULES.md)。
- 名称使用用户已校正的「高築道叶」「比企政員」。年龄基准1563年，原始统率1～6。
- 主将画像260×260，两副将各200×200；左右并列，不精简人物信息。状态行无悬停提示，操作提示／关闭采用繁体中文，界面尽量只用日本汉字。
- 现有成品12类×8色=96张；代码10类。`槍武士隊` 对应 `徒歩武士` 尚未确认；`近習騎馬隊`、`騎馬鉄砲隊` 缺运行配置。不要从画面推定数值。
- 代码不会从素材文件名自动识别兵种，也不会自动加载 GitHub PNG。用户在 TTS 选择底图、加 Tags；武将／旗图片填 Description。动态图片直链见 `docs/tbs/runtime-assets.json`，这只是源码快照，不是运行时加载配置。
