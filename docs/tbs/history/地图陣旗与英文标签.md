# 地图陣旗与英文标签

更新：2026-10-11，适用于 v2.10（地图旗沿用 v2.9.1 修复）。

v2.9.1 针对「侧边面板有阵旗、棋子旁只有白块」调整图片绑定：地图旗与侧栏一样引用主将 `flag_image` 的完整 URL；首次挂载、重建或更换资源后，在 Object UI 可写时补一次图片绑定。原有描述和标签继续使用，无须重填。此修复通过脚本模拟检查，实际纹理显示仍需在 TTS 确认。

普通部队用英文标签表示所属備隊，界面仍显示「太田家 本陣」等汉字名称。不需要在标签输入框打汉字，也不用在每枚普通部队的 Description 中重复填写图片地址。这里没有假定 TTS 一律不支持汉字；使用英文 ID 是为了避开你遇到的输入问题。

## 1. 安装新版 Global

1. 先另存当前 TTS 游戏。
2. 打开[完整 Global 脚本](C:/Users/HP/Documents/ChatGPT/日本战国/TTS武将面板/兵種与備隊面板合并版_日本漢字.lua)，复制全部内容。
3. 完整替换 **Scripting → Lua → Global**，然后点击 **Save & Play**。不要追加到旧脚本末尾。
4. 之前的兵种功能、武将资料、侧边画像与陣旗继续使用原来的设置。如果你后来修改过其他 Global 功能，按[合并方法](C:/Users/HP/Documents/ChatGPT/日本战国/TTS武将面板/与现有Global合并方法.md)保留那些改动。

完整 Global 已内嵌地图陣旗模块，不需要另粘一份模块，也不用在每枚棋子的 Lua 中添加脚本。

## 2. 太田家本陣：先确认主将图片地址

地图上的陣旗和侧边面板共用主将 Description 中的 `flag_image`。太田資正保留原有资料，并确认这三项正确：

```text
team=ota_honjin
role=main
flag_image=
```

把云端图片直链填在 `flag_image=` 后面。若还没有直链，先按[新陣旗使用说明](C:/Users/HP/Documents/ChatGPT/日本战国/TTS武将面板/新陣旗使用说明.md)上传[太田家三紋陣旗 PNG](C:/Users/HP/Documents/ChatGPT/日本战国/TTS武将面板/素材/太田家_三紋陣旗_v1.png)。不要把本地文件路径填进去，也不要用这三行覆盖主将完整 Description。

每隊只保留一个 `role=main` 的主将。主将缺失、重复，或 `flag_image` 为空、`-`、无效地址时，地图不显示该隊陣旗。

## 3. 给普通部队添加所属标签

1. 右键一枚属于太田家本陣的普通部队，选择 **Tags**。
2. 在标签窗口底部输入 `ota_honjin`，创建该标签。
3. 在标签列表中确认 `ota_honjin` 已启用。给本陣其他部队选择同一个标签。
4. 保留棋子已有的兵种等标签，只增加这一项所属标签。
5. 指向其中一枚部队，或者点击面板「更新」，让脚本识别新归属。

这是真正的物件 **Tags**，不是在 Description 中写 `tag=ota_honjin`。普通部队只用标签即可关联整隊，不必另写 `role=unit`、`image` 或 `flag_image`。

TTS 官方说明：只有房主能创建新标签，获提升权限的玩家可以切换已有标签；这与本脚本的面板按钮权限不同，本脚本不限制只有房主能操作面板。[TTS 标签说明](https://kb.tabletopsimulator.com/game-tools/object-tags/)

| 備隊 | 物件 Tags 中输入 | 主将 Description 的 `team` |
| --- | --- | --- |
| 太田家 本陣 | `ota_honjin` | `ota_honjin` |
| 太田家 岩付衆 | `iwatsuke_shu` | `iwatsuke_shu` |
| 太田家 江戸衆 | `edo_shu` | `edo_shu` |
| 太田家 松山衆 | `matsuyama_shu` | `matsuyama_shu` |

这些英文 ID 必须准确，包括下划线。不要写成 `太田家本阵` 或 `ota honjin`。

一枚棋子只启用一种所属标签。兵种等无关标签可以同时存在。若误启用了两个指向不同備隊的所属标签，脚本不会替你选择其中一隊，应去掉多余所属标签再点「更新」。若棋子已有 Description 的 `team=`，所属标签优先；改变所属标签时也建议把旧的 `team=` 同步改好或移除，避免以后去掉标签又回到旧隊。

主将和副将仍需保留各自的 `role=main`、`role=deputy1`、`role=deputy2` 和人物资料；不要把普通部队模板覆盖在武将上。已经通过 Description 正确配置的武将可以直接被识别，不要求重填全部资料。

## 4. 地图上的显示方式

| 场景 | 显示 |
| --- | --- |
| 平时 | 配置完整的主将旁边显示长旗，普通部队收起旗。 |
| 鼠标指向本隊一枚棋子 | 当前棋子展开长旗，同隊其他棋子出现轮廓高亮。 |
| 点击「本隊陣旗：無」 | 变为「本隊陣旗：有」，当前所看備隊的棋子展开较小的旗。 |
| 再次点击「本隊陣旗：有」 | 收起这次全隊展开，恢复平时和悬停显示。 |

阵旗图片不拦截鼠标，因此可以继续拿取棋子。它仍是地图上的视觉标记，密集排布或斜视时可能遮住邻近内容；需要细看接战区时，先关掉全隊展开。它不改变棋子的占格、兵种数值或行动状态。

「本隊陣旗」位于面板最下方一排的最左侧，其他底部按钮略收窄，面板仍为 `600 × 1000`。没有可用主将陣旗地址时，开关不可点击，但悬停识别和同隊高亮仍可使用。

未固定面板时，换看其他備隊会自动收起原隊的全隊旗。固定面板时，按钮始终作用于固定的隊；鼠标经过别隊时，悬停旗和高亮仍跟随实际指向的棋子。点击「關閉」会清除该座位本次悬停和手动展开，主将常驻旗保留。

全隊旗开关和悬停旗按座位颜色分别显示，主将常驻旗对所有人显示。TTS 的轮廓高亮则是共享桌面效果：多人同时查看不同隊时，会同时出现对应队伍的高亮，不是只有操作者能看到。多个 Grey 旁观者共用 Grey 的面板和开关。换座位颜色、离线或重新读档会清除临时悬停与展开状态。

### 大小、位置和兼容性

地图旗以棋子为参照，平放在其右后侧；它随棋子的位置和朝向移动，不是始终朝向镜头的立体旗杆。长旗高约为棋子平面较短边的 `80%`，全隊展开的小旗高约为 `45%`，宽高比均为 `3:8`。边缘间隙约为短边的 `4%`，略高于棋子表面，以减少重叠闪烁。翻面后会调整旗的方向，主将仍保持长旗。

这些尺寸依据物件归一包围盒计算；厚度、模型轴向和非等比缩放可能影响实际观感。当前 Object UI 换算使用每个物件局部单位 `100` 个 UI 单位，抬高量 `0.03` 个世界单位，仍需在你的 TTS 令牌上校准。若需调整，在完整 Global 中搜索 `MAP_FLAG_BIG_HEIGHT`、`MAP_FLAG_SMALL_HEIGHT`、`MAP_FLAG_SIDE_GAP`、`MAP_FLAG_LIFT` 或 `MAP_FLAG_UI_UNITS`。地图旗参数与侧边面板的 `90 × 240` 旗位、背面「済」印章参数相互独立。

脚本读取棋子当前的 Object UI，保留已有 XML 节点和图片资源，追加自身的 `sgmf_` 节点；后续显示变化只更新自己的属性。但首次挂载或清理地图旗需要重新提交 Object UI，TTS 无法可靠返回第三方 `allowDragging` 界面拖动后的屏幕位置，因此此类拖动位置可能重置。若棋子已有可拖动的自定义界面，先在存档副本中检查；不保证与所有第三方 Object UI 组合都完全无影响。

地图旗的 `image` 使用完整 URL，`sgmf_flag` 仍作为物件图片资源登记；登记资源不等于直链图片已缓存。TTS 官方允许图片属性使用 URL，但说明该方式不缓存图片。脚本只在初次挂载、必要的加载后补写和地址改变时设置图片，不会每轮定时刷新都重新写入地址。[TTS 图片属性](https://api.tabletopsimulator.com/ui/attributes/#image-attributes)

## 5. 新增其他備隊

四支内置隊直接使用上表标签。自己增加的新備隊使用 `sg_team_` 加上 `team` ID 的标签，例如：

```text
主将 Description：team=new_sonae_01
普通部队 Tags：sg_team_new_sonae_01
```

上面两行是位置说明，不要原样粘贴为 Description。主将仍填写 `role=main`、姓名和 `flag_image`，副将使用同一 `team`，角色分别为 `deputy1`、`deputy2`。通用标签去掉 `sg_team_` 前缀后，必须与主将的 `team` 一致。新隊的汉字显示名称在主将 `formation=` 中填写。

## 6. 修改后检查

- 给一枚本陣部队启用 `ota_honjin`，指向它，确认侧边显示太田資正所在隊。
- 确认主将旁边有旗，普通部队在悬停时出旗，其他本隊成员高亮。
- 点击「本隊陣旗」，确认全隊展开，再点击收起；陌生队伍不应一起展开。
- 切换标签、复制或新建棋子后，点击「更新」重新扫描。悬停、放下棋子也会更新其归属。
- 如果没有旗，先看主将侧边画像旁的旗能否显示，再检查主将是否重复、URL 是否完整、所属标签是否准确。
- 最后保存 TTS 游戏，保留标签和 Description 的改动。

目前提供脚本与模拟检查；旗的位置、朝向、不同模型的尺寸以及多人显示仍需在实际 TTS 桌面确认。侧边面板原有 `90 × 240` 陣旗布局不变；背面「済」印章参数 `BACK_STAMP_RATIO=1`、`BACK_STAMP_GAP=-0.09` 保留。
