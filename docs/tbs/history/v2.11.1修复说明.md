# v2.11.1：长图片地址与数字高度修复

更新：2026-10-13。

使用本目录 `兵種与備隊面板合并版_日本漢字.lua` 全部替换 TTS Global，再 **Save & Play**。保留了自动存档中你已填写的敗走图片直链，其他游戏存档文件未修改。士气数据格式、点击方式、部队标签和右栏坐标不变。

## 报错原因

旧 `unitDefeatURL()` 的 `^%s*(.-)%s*$` 在本机 TTS 所带 MoonSharp 中处理 65 字符及以上的普通 URL 时可触发 `pattern too complex`。你的实际 Steam 地址长 106 字符，已复现同一错误。这与图片分辨率无关。

新解析器逐字符扫描，不调用 `match`、`gsub` 或 `gmatch`。保留整个地址和查询参数，处理首尾换行、普通空格、NBSP、全角空格和 BOM。图片处理失败会保留敗走文字；单枚棋子初始化失败也不会再中断后续部队。

## 数字高度

自动存档中 25 枚匹配部队都是厚度 0.1、缩放 0.4／1／0.4 的 Custom Tile。新版本恢复先前棋子使用的局部高度：

```lua
UNIT_NUMBER_FRONT_Y = 0.11
UNIT_NUMBER_BACK_Y = -0.01
```

正面数字平面在上表面外，背面在下表面外。这两个值位于脚本顶部；填 `nil` 时才采用自动高度。宽、深仍按模型计算，但改为优先读取碰撞体边界，并在清除旧按钮后测量，以免旧显示层影响几何结果。

如果更新后数字仍被模型遮住，可先把正面调到 `0.14`、背面调到 `-0.04`，再 Save & Play 检查。若仍然全无数字，继续增加高度并不能证明能解决，需要检查实际按钮坐标和模型朝向。

## 貼花偏移与数字高度分开

已按你的最新要求在完整 Global、武将独立版及其别名中同步：

```lua
local BACK_STAMP_GAP = -0.099
```

这只控制武将背面「済」印。背面貼花最终 Y 的计算是 `背面局部位置 - GAP`，所以 `-0.099` 会向棋子内部移动 0.099；它不是数字平面的绝对 Y。厚度 0.1 时，`-0.1` 刚好接近跨过整个厚度，你观察到的消失现象与投射范围有关；仍需以实机为准。

部队「敗走」贴图独立使用：

```lua
UNIT_DEFEAT_FRONT_GAP = -0.09
UNIT_DEFEAT_BACK_GAP = -0.09
```

这些值参考此前可见的済印偏移，不随本次武将済印调整自动改变。`UNIT_DEFEAT_IMAGE_ASPECT` 仍为 2（图片宽÷高），需要按实际素材比例填写。

TTS 的按钮是附着在棋子上的界面元素，贴花有单独的位置、旋转和投射尺寸；两类参数不能等同使用。参见 [官方按钮接口](https://api.tabletopsimulator.com/object/#createbutton)和 [Decal 接口](https://api.tabletopsimulator.com/object/#adddecal)。

## 验证范围

已使用 TTS 随游戏安装的 MoonSharp 复现旧错误，并验证新解析器可处理真实地址及最长 16,384 字符测试地址；同时回归正反面坐标、已校准高度、存档和其他贴花共存。没有改动游戏自动存档；也没有把参数模拟通过当成实际 TTS 渲染已验证。
