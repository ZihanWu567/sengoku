# v2.14.9：首次创建背面 UI 时的空引用

v2.14.8 新增的隐藏旧画面检查，在 Object.UI 尚未创建时调用了 `getAttribute()`。本机 TTS 的空 UI 可以同时满足 `loading=false`、`getXmlTable()={}`，但 `getAttribute()` 仍会因内部 `xmlLayout` 为空而抛出 `Object reference not set to an instance of an object`。

此问题是上一版检查顺序错误引入的。

修复：通过 `getXmlTable()` 返回的 Lua 表查找节点；只有节点已存在时才更新属性。保留 v2.14.8 的显式图片登记流程、云端地址、兵种数值与显示位置。

实机证据：同一枚棋子 f3e5ec 上，旧属性查询触发原生空引用；新判断成功返回 `rootExists=false, safeGuardCompleted=true`。没有修改棋子状态或存档。证据位于 `验证工具/空界面单步_实机.error.json`、`验证工具/空界面资源_实机.json` 和 `验证工具/空界面修正后_实机.json`。

自动测试新增空 UI 属性查询会抛异常的模拟条件。合并版 3082 项检查、两份独立面板各 1168 项检查及 XML/事件入口检查全部通过。此次实机测试验证了报错调用的修正，尚未在游戏中重新加载整份新脚本验证最终颜色。

使用：完整复制 `Global_完整替换版_v2.14.9.txt`，替换 Global Lua 后 Save & Play。
