# 背面士气 PNG 显白：安装版引擎只读审计

日期：2026-10-19。未修改任何 Lua 主脚本或游戏存档。

## 已验证事实

读取当前安装的 `Tabletop Simulator_Data/Managed/Assembly-CSharp.dll`、`XmlLayout.dll`、`UnityEngine.UI.dll` 的方法 IL。主要证据保存在同目录的 `背面士气图像引擎审计_20261019.txt`。

1. `XmlUIObject.OnTextureFinish` 会在当前对象的 `CustomAssets` 中按 URL 顺序查找第一条匹配记录，取该记录的 Name。仅这一名称会注册到全局 `XmlLayoutResourceDatabase`。如果同一对象的资源表用不同名称登记相同 URL，后面的别名不会由这个回调单独登记。这是一个明确的失败条件，但尚无证据证明当前士气资源表触发此条件。
2. 预载回调将 `Texture2D` 的完整区域构造成 Sprite，矩形是 `(0,0,width,height)`，pivot 为 `(0.5,0.5)`，pixelsPerUnit 为 100。没有 144×24、宽高比、正方形、2 的整数幂或颜色相关的分支。
3. `ImageAttribute.Apply` 先以 `image` 属性原值查询资源数据库。已存在的名称或 URL 都走同步绑定。若未找到且属性是 URL，另走 XmlLayout 的下载器。若未找到且不是 URL，输出 `[XmlLayout] Unable to load sprite '...'` 后返回，并不重新下载这个别名。
4. XmlLayout URL 下载器调用 `UnityWebRequestTexture.GetTexture(url)`，而预载和贴花使用 TTS 的 `CustomLoadingTexture`。因此正面贴花成功能证明 URL/PNG 在贴花路径可用，但不能单独证明背面 XML UI 已绑定 Sprite。
5. XmlLayout URL 下载器下载完成后同样对完整图片做 `Sprite.Create`；没有图片尺寸或颜色限制。其错误分支检查 `isNetworkError`，未在同一方法中额外检查 HTTP 状态。这个差异需要结合游戏日志才能判断是否相关。
6. `ImageAttribute.Apply` 在未指定 color 属性时默认设为白色；正常使用白色 tint 不会把真实彩色贴图变成白色。
7. Unity `Image.get_mainTexture` 明确规定：有有效 activeSprite 时返回其 texture；没有 Sprite 且没有材质主纹理时返回 `Graphic.s_WhiteTexture`。所以全白矩形与“未绑定 Sprite”相符，但仅从截图仍不能排除其他材质/纹理状态。
8. `ConversionExtensions.ToSprite` 对 `sgub_band_amber`、`sgub_band_red` 没有特殊命名解析，也没有自动添加对象 GUID；资源名大小写及确切字符串需要匹配。

## 尚不能下结论的部分

- 不能根据 144×24 或 378 字节文件大小宣布图片不受支持：上述两条 Sprite 创建路径都没有这类条件。
- 不能把缺图肯定归因于网络：v2.14.6 已改用预载名称，需检查运行中实际 Sprite、预载表和日志。
- 不能把原生颜色替代方案称作解决了图片加载根因。

## 运行时最有区分力的证据

检查出问题对象的 `sgub_morale_band` 的 image/active/color 属性、CustomAssets 中 URL 与 name 的对应，以及 Unity `Image.sprite`/`overrideSprite`/`mainTexture`。若 Sprite 为 null，进一步区分“别名未注册”与“属性没应用”；若 Sprite 非 null 且 texture 有正确尺寸，则查实际纹理/材质绑定。与同一对象正常的数字 Image 做对照。
