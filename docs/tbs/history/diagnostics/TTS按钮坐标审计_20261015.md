# TTS 经典按钮与贴花坐标审计

只读检查安装版 `Assembly-CSharp.dll`，没有执行游戏对象或改动存档。

## 确认的引擎行为

- `LuaObject.ActionCreateUI` 的 IL `0065..0079`：按钮父节点 `LuaPanel` 的局部欧拉角为 `(-90, 180, 0)`，位置为零、缩放为一。
- `LuaObject.SetUI` 的 IL `0007..0036`：API 传入的 `(x,y,z)` 被写入按钮子节点为 `(x,z,y)`。
- 两项组合后，实际对象局部位置是 **`(-x,y,z)`**。这与直接使用对象局部位置的贴花不同。
- `SetUI` 的 IL `003B..00A3`：按钮子旋转为 `Euler(api.x,api.z,api.y) * Euler(180,0,0)`。
- `SetUI` 的 IL `00A8..0155`：基础缩放为 `0.00208 * 3`，API width/height 各除以 3 后取整。最终宽度约为 `API width * 0.00208 * API scale.x`（另有取整误差）。

## 对当前棋面应采用的变换

先按现有 `unitImagePosition` 求出贴花的真实对象局部坐标 `p`，增加必要的按钮高度偏移后：

```lua
button.position = {-p[1], p[2], p[3]}
button.rotation = back and {0,0,180} or {0,0,0}
```

注意负号作用于完整的 `p[1]`，包括 `geometry.cx`。不能只反转离几何中心的偏移。

上述按钮旋转分别对应当前贴花的前面 `Euler(90,180,0)`、背面 `Euler(270,0,0)`。旧按钮 `rotation.y=180` 额外把内容旋转半周，透明方形点击区域看不出差别，但备用数字或行动文字会受影响。

若想让点击框与图片尺寸更严格一致，可把 `button_units_per_local=500` 改为 `1/0.00208`；前者约大 4%，与左右错位无关。引擎还会对 width/height 三等分取整，因此不应要求浮点像素级完全相等。

## 回归测试应验证的对象

测试不要只比较 API 表里的 button.position 与 decal.position。应先把按钮经过引擎变换 `(-x,y,z)`，再比较两者；包含非零 `geometry.cx` 的用例。前后面、行动按钮、士气按钮、更新和首次创建都应覆盖。

## 可复现方法

运行 `只读审计TTS按钮IL.ps1`，筛选 `ActionCreateUI` 与 `SetUI`。原始输出已存为 `TTS按钮坐标IL_20261015.txt`。

官方 API 说明（https://api.tabletopsimulator.com/object/#createbutton）只描述相对位置及按钮的单面点击限制，没有披露父节点的内部坐标转换。因此本结论依据本机安装版程序集，不是由 Lua mock 的输出推断。
