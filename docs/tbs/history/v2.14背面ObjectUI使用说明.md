# v2.14：背面数值栏改用同一 Object.UI

更新日期：2026-10-17

## 安装

1. 在 TTS 中保存一份当前存档。
2. 打开本目录的 `兵種与備隊面板合并版_日本漢字.lua`，复制全文。
3. 在 TTS 的 **Scripting → Global → Lua** 中替换原有全部代码，然后 **Save & Play**。不要追加到旧代码后面；无需手动填写 XML 页。
4. 首次加载需要等待图片资源完成下载。无需修改棋子 Description、标签或重新上传素材。

原版代码备份位于 `修复前备份/v2.14背面ObjectUI前_20261016_235233/`。

## 本次变化

- 背面深色底栏、兵数、士気、移動、未／済，改为同一个物件 UI 内的五张图片。底栏最先绘制，其余图片随后绘制，所有图片位于同一 UI 平面。
- 自动移除旧版对应的五个背面贴花，避免旧显示与新 UI 重复。
- 保留现有 22 个云端图片地址，包括外边缘透明的底栏和行动图片。
- 点击已加载的背面数字或行动角时，只更新对应图像，不重建整个 UI 或重新登记全部资源。图片加载期间发生的操作在加载完成后按最新状态显示。
- 背面 UI 固定在棋子实际下表面外侧，随棋子移动、翻转和缩放；不需要每帧检查翻面状态。
- 清理部队标签或销毁棋子时，只清理本模块的 UI、贴花及等待任务，保留其他模块的 UI 和资源。

正面数字、阵旗、敗走图、武将面板和士气规则继续沿用原有行为。士气数字左键加一、右键减一；正面耗尽后自动翻面并恢复背面士气，背面耗尽后敗走；未／済仍是独立的行动状态，所有玩家均可操作。

## 为什么不再调整层间距

背面长底栏和小数字原先是独立的透明贴花。安装版本的贴花材质使用透明混合且不写入深度，多个贴花可能随摄像机方向改变前后排序。增加间距不能可靠解决这种问题。

现在这五张图在同一个 UI 中按固定节点顺序绘制。无需为各兵种、各家族额外制作背面底图。

旧的 `UNIT_OVERLAY_SEPARATION` 已移除。`UNIT_DEFEAT_FRONT_GAP`、`UNIT_DEFEAT_BACK_GAP` 仍控制原有贴花；它们不再控制背面数值栏。背面 UI 的整组离面距离集中在 `UNIT_COUNTER_LAYOUT.back_ui_clearance`，已按用户 2026-10-17 的实测结果设为 `-0.099`。整组图像和点击面会一起移动；`hit_lift = 0.004` 保持不变。该值适用于用户当前棋子模型，不是所有模型通用的表面坐标。

## 验证范围

已用本机 TTS 自带的 MoonSharp 运行 Lua 语法及模拟行为回归：合并版通过 2,881 项检查，独立武将面板两个文件分别通过 1,168 项，另通过 42 项 URL 解析检查。覆盖状态转换、保存读取、即时换图、异步加载、资源与第三方 UI 保留、旧贴花清理和销毁后回调保护。已核对安装版世界空间 UI 的坐标换算、缩放继承和背面朝向。

尚未在实际 TTS 中完成斜视角渲染及联机鼠标点击验收。安装后请重点检查：从棋子的两端倾斜观察背面时，三项数字与未／済均保持可见；点击位置与显示位置一致；翻回正面后仍显示原有正面样式。

实现所用接口见 [TTS UI API](https://api.tabletopsimulator.com/ui/) 和 [UI 属性](https://api.tabletopsimulator.com/ui/attributes/)。本地材质审计记录见 `验证工具/TTS背面贴花透明排序审计_20261016.md`。
