# v2.14.8：背面色带的图片登记修复

## 查到的原因

2026-10-19 通过 TTS 本机外部编辑器接口检查了当时运行的 v2.14.6。

- 棋子 `f3e5ec` 的背面色带引用 `sgub_band_amber`；`UI.loading=false`，但 `UI.getCustomAssets()` 返回空表。
- 同一 UI 的数字、底栏和行动图使用直接网址，因此它们正常显示不能证明色带名称已经登记。
- 对同一枚棋子调用 `UI.setCustomAssets()`，相同的琥珀、朱红网址立即进入资源表，加载后仍保留。
- 随后调用 `UI.setXmlTable(原界面, 两张图片加测试别名)`，加载完成后资源表依然只有原来的两项；第二参数中的新别名没有登记。
- 本机缓存中的两张 PNG 有正确颜色。安装版图像加载代码未发现 144×24 或非正方形 PNG 的特殊限制。

这次运行版本的直接故障是：**界面引用了未登记的图片名称**。Unity Image 在没有 Sprite 时可显示默认白纹理。此前增加间距或用纯色替代没有修正这一资源登记错误。

[官方 UI 文档](https://api.tabletopsimulator.com/ui/#setxmltable)列出了可选的第二个资源参数；本机实测行为与之不一致。本次修复使用单独的 `setCustomAssets()`，不依赖该重载。此结论针对本次检查的安装版，不推广到所有 TTS 版本。

## 修改

1. 先显式登记图片并等待加载完成，再用单参数 `setXmlTable()` 创建背面 UI。
2. 色带继续使用原有两张 PNG，恢复图片方案；正面黑字、背面象牙白字及已校准高度保持不变。
3. 图片配置改变时先隐藏旧画面，加载结束后读取最新士气和行动状态。
4. 修正地图阵旗模块中相同的双参数调用；保留其他脚本的 UI 节点和资源。
5. 日常士气增减只修改已有节点，不重新登记图片或重建整个 UI。

## 使用

把 `Global_完整替换版_v2.14.8.txt` 全部复制到 TTS 的 Global Lua 中，再 Save & Play。现有云端地址、兵种配置和游戏规则已保留。

验证一枚長柄足軽：背面满士气 5 时无色带，减到 4 显示琥珀，减到 2 显示朱红，恢复到 5 隐藏；数字应仍为象牙白。检查点击士气与未／済仍正常。

## 验证范围

实际 TTS 运行时已完成“登记前空表 → 单独登记成功 → 双参数附加资源无效”的对照测试，证据在 `验证工具/色带运行态_*.json`。

自动检查使用本机 TTS 的 MoonSharp；对象 UI 模拟器已改为忽略 XML 接口的资源参数，并要求色带别名先登记再绑定。自动检查不代表游戏中的视觉验证。

最终检查通过：合并版 3082 项行为断言；两份独立面板各 1168 项。三份脚本的 XML、按钮回调、唯一 ID 及事件入口检查均通过。完整替换 TXT 与合并版 Lua 逐字节一致。

实机颜色复核时 TTS 已关闭；关闭后无法继续截图，也无法执行临时诊断 UI 的恢复指令。本次没有执行 Save & Play、写入游戏存档或修改部队士气/行动数值。诊断期间临时给一枚满士气棋子显示了琥珀色带，并移动了观察视角；动态 UI 不写入本项目的保存逻辑。重新加载游戏会由脚本重建界面。
