# 部隊右欄 v2.11

更新：2026-10-13。适用于 1200 × 1200、右侧三格的十色完整底图。

## 安装

1. 在 TTS 保存当前游戏。
2. 打开本目录的 `兵種与備隊面板合并版_日本漢字.lua`，复制全部内容，完整替换 **Scripting → Lua → Global**，点击 **Save & Play**。不要在旧脚本后面追加；本文件已经包含武将面板和阵旗模块。
3. 部队沿用现有标签，例如 `unit_nagaye_ashigaru`、`count_100`、`ota_honjin`。不再需要 `unit_ui_v2` 标签；已有该标签也无妨。当前这套数值配置仍是長柄足軽，增加其他兵种应另行补充 `UNIT_CONFIGS`。
4. 所有命中 `UNIT_CONFIGS` 的部队都会采用右栏新排布，应配套使用新底图。部队名和「兵数／百人／士気／移動」由底图提供，脚本不会重复显示这些文字。

此前游戏内如果另有尚未保存到本地文件的自定义代码，应把它保留在新版中。本次修改前的本地文件在 `修复前备份/部隊右欄修改前_20261012_223927/`。

## 数值和操作

| 内容 | 显示 | 操作 |
| --- | --- | --- |
| 兵数 | `count_100` → 1；200 → 2；300 → 3；400 → 4 | 只读；一枚部队保留一个人数标签 |
| 士気 | 原存档的正反面独立数值 | 左键加 1，右键减 1；正面上限 6，背面上限 5 |
| 移動 | 正面 4，背面 3 | 只读 |
| 敗走 | 上传图片后用图片；地址为空时用文字 | 右键棋子 →「敗走表示切替」 |

不更改已有士气、上限或存档格式。新棋子依然按原规则初始化为 0；原规则「背面士气为 0 则显示敗走」也保留，手动开关不会抵消这个自动条件。示意图中的 6／4 不是新棋子的初始值。

数量标签改好后再 Save & Play，重建显示。三个数值没有白底或悬停提示；只有士气数字区域拦截点击，兵数和移动是文字显示。

## 阵旗

部队阵旗移入立绘区，贴着右侧数值栏的左边。仍从主将 `flag_image` 读取图片，仍按既有的悬停大旗／本队展开小旗规则显示。

- 以 1200 方形棋面计，大旗 270 × 720，小旗 180 × 480。
- 右边缘为 x=976，与数值栏分隔线 x=1000 留 24px 间隔。
- 垂直中心 y=700；大旗覆盖 x=706～976、y=340～1060。
- 旗贴近部队表面，叠放武将时允许遮挡。主将和副将令牌原有外侧旗位置保留。

## 敗走贴图：以后只填一次地址

脚本顶部已经预留：

```lua
UNIT_DEFEAT_IMAGE_URL = ""
UNIT_DEFEAT_IMAGE_ASPECT = 2
```

日后上传现有图片后，把完整图片直链填进引号内。全军共用，不必逐枚写 Description。`ASPECT` 填原图的 **宽÷高**：600×300 为 2，正方形为 1。推荐有透明背景的 PNG，避免白色矩形覆盖立绘。上传与取得链接可参考 [TTS Cloud Manager 官方说明](https://kb.tabletopsimulator.com/custom-content/cloud-manager/)。

填好后 Save & Play。触发敗走时在正反面各添加一份自有贴花，同时隐藏旧文字；恢复时删除。其他贴花会保留，阵旗的 Object UI 也不会被替换。这里使用 TTS 的 [Decal 接口](https://api.tabletopsimulator.com/object/#setdecals)。

默认贴图中心为完整底图的 x=450、y=720，宽 480px；高按原图比例计算，最高 700px。在 `UNIT_COUNTER_LAYOUT` 中可调整 `defeat_x`、`defeat_y`、`defeat_width`。位置避开右侧数值栏和阵旗区域。

空地址、格式不正确或贴花 API 设置失败时，暂时保留「敗走」文字，避免状态提示消失。**有效地址不等于图片已成功下载**；网络下载失败仍需检查直链。要临时恢复文字，可清空 URL 后 Save & Play。当前没有上传图片，也没有验证你的图片在 TTS 中的实际朝向。

## 数字是否改贴图

视觉上推荐最终采用与底图同款的 **Source Han Serif JP Bold（思源宋体日文 Bold）** 数字 PNG，这样笔画和比例最统一。数字图片负责外观，透明按钮继续负责士气左／右键操作。TTS [经典按钮](https://api.tabletopsimulator.com/object/#createbutton)可以调字号、颜色和缩放，但没有指定字体文件的参数。

当前交付先用动态文字，无需额外上传数字素材。数字图片方案尚未启用；需要先准备并上传数字素材，再实现数字替换及资源加载。大军推演中应共用一套素材，避免为每枚部队单独创建图片。

## 尺寸与验证边界

脚本按棋子视觉边界换算到模型局部坐标，并分别计算正反面。完整底图上的数值中心：兵数 (1100,374.5)、士気 (1100,748)、移動 (1100,1081.5)。`UNIT_COUNTER_LAYOUT` 的 `text_offset_y` 可微调字体视觉中心（底图像素，正数向下），`font_pixels` 可调整字号。

附带 HTML 为布局模拟，不是 TTS 截图。MoonSharp 回归验证逻辑、数据和几何参数；TTS 的实际字体视觉中心、经典按钮尺寸换算、贴花投射与背面朝向仍需在游戏里核对。
