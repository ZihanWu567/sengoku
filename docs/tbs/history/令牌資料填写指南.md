## 1. 安装更新后的 Global 脚本

1. 先在 TTS 中把当前游戏另存为一个副本。
2. 打开本文件同目录的 `兵種与備隊面板合并版_日本漢字.lua`，复制全部内容。
3. 在 TTS 打开 **Scripting → Lua → Global**，全选原有代码，用新代码完整替换，然后点 **Save & Play**。
4. 不要把新脚本追加到原代码下面；重复的 `onLoad` 等函数会影响初始化。

当前为 **v2.10**，合并文件第一行包含版本号 `v2.10`。所有玩家都可以操作，不需要房主或管理员身份。安装后，先指向武将令牌显示備隊，再点击「状態」右侧带底色的状态值。它会循环切换「無傷 → 浅手 → 深手 → 討死 → 無傷」并保存到该令牌的 Description。「状態」是固定、无底色的标签，不随切换改变。界面由 Global Lua 自动生成，只更新 Description 不会安装按钮功能。若状态显示「未配置」或「配置重複」，按钮会禁用；应先补齐令牌或解决同队同角色重复，再点「更新」。

所有武将的面板行動印与令牌背面「済」贴花统一使用你提供的同一张图片，不必再逐枚填写印章地址。武将画像仍由各令牌的 `image=` 单独设置。

十二种座位颜色各有自己的面板：查看队伍、固定、关闭和缩放互不影响。状态和当前命令写入桌上令牌，所有正在查看同队的人会同步看到更新。Grey 旁观者也能操作；多个 Grey 旁观者共用 Grey 面板。

这个合并版包含之前提供的兵种功能。如果你之后又在游戏内改过 Global，请先保留那些改动，再合并到新版本。如果旧 Global 已经填过画像地址，先复制这些地址，填进下面对应令牌的 `image=`。

当前版本保留了刷新与资源管理优化：稳定的定时资料刷新不再重复测量背面贴花尺寸或读取贴花，贴花仍在加载、新建令牌、悬停、放下和点击「更新」时校验。非等比缩放令牌或手动改过贴花后，可以重新悬停或点击「更新」进行校验。画像与陣旗等本脚本 Global UI 自定义资源登记最多保留 `64` 份当前及近期使用的资源，其他脚本的资源照常保留。这是登记数量的限制，不代表直链图片已经缓存，也没有据此宣称帧率提升。合并版还对格式异常的旧存档资料做了容错处理。

## 2. 在令牌中填写资料

右键武将令牌，找到 **Description（描述）**，把对应模板完整粘贴进去。令牌的 Name（名称）建议也填写为正确的武将姓名，方便在桌上辨认。

每行格式是 `字段=内容`，不用加引号。一条资料占一行，尤其不要把画像地址拆成多行。

| 字段 | 填写方法 |
| --- | --- |
| `team` | 同一备队的三名武将填写完全相同的 ID；不同备队必须不同。只使用英文字母、数字、下划线或连字符。 |
| `role` | 主将填 `main`，两名副将分别填 `deputy1`、`deputy2`。 |
| `name` | 面板上显示的姓名，例如 `太田資正`。 |
| `birth` | 生诞年份，例如 `1522`。年龄按 `1563 - birth` 计算，不必另填年龄。 |
| `command` | 原始统率，填写 `1`～`6` 的整数。受伤时不修改这个字段；面板按状态计算当前值。 |
| `image` | 画像的完整云端图片直链。留空会使用该武将的内置画像；填 `-` 表示明确不显示画像。 |
| `flag_image`／`陣旗` | 仅在主将令牌填写本隊陣旗的完整图片直链，二选一作为字段名即可。留空或填 `-` 时隐藏陣旗；副将中的该字段不读取。 |
| `status` | 推荐填写 `無傷`、`浅手`、`深手` 或 `討死`。也可以直接点击面板中「状態」右侧的状态值循环切换。旧值 `健康`、`軽傷`、`重傷`、`陣没` 仍能识别，显示时使用新名称。 |
| `title` | 可选的职务显示；模板中主将用 `備大将`，副将用 `副将`。 |
| `formation` | 在主将令牌填写备队显示名称，例如 `太田家 本陣`。 |
| `order` | 在主将令牌填写当前命令：`攻撃`、`防御`、`機動` 或 `再編`。 |
| `acted_image` | 旧版行動印字段。v2.9 保留原描述内容，但不读取这个设置；包括旧地址和 `-` 都不会覆盖或关闭统一「済」印。可以删除这一行。 |

机动固定为無傷 `9`、浅手和深手 `4`、討死 `—`，不必填写机动字段。行动状态由令牌正反面决定：正面朝上显示 `未`，翻面显示 `済`。翻面时，统一印章盖在面板画像右下角，桌上的武将令牌背面也有同一张「済」贴花。翻回正面，面板印章隐藏、行動恢复 `未`；背面贴花仍保留在反面，无须反复创建或删除。

状态按钮直接写回当前武将令牌的 Description；所有玩家都可以执行，修改后同队面板同步刷新。点击后写入的是新名称，例如 `status=浅手`，不必先把旧描述逐枚改写。

| 状态值 | 面板上的統率数字 | 機動 | 显示效果 |
| --- | --- | --- | --- |
| `無傷` | 原始统率 | `9` | 绿色状态值，普通外框。 |
| `浅手` | 原始统率 | `4` | 浅红状态值、外框和 `浅手` 角标。 |
| `深手` | 原始统率减 `1` | `4` | 深红状态值、外框和 `深手` 角标；画像略暗，最后一个原始实心圆直接替换为 `X`。 |
| `討死` | `X` | `—` | 六格全部显示 `X`；画像、卡片背景、姓名和能力文字进一步压暗。 |

例如 `command=5`、`status=深手` 时，数字显示 `4`，六格显示 `●●●●X○`；原始统率为 `2` 时，数字显示 `1`，六格显示 `●X○○○○`。原始统率为 `1` 时，深手数字显示 `0`、六格显示 `X○○○○○`；原始统率为 `6` 时，深手数字显示 `5`、六格显示 `●●●●●X`。失效格只显示 `X`，不在圆圈中叠加叉号。不另设有效统率栏，也不把扣减后的数值写回 `command`，因此恢复無傷后会自动恢复原值。

討死画像使用深灰色调制进行压暗；这是对原图颜色的乘色处理，不是真正的黑白转换，原图中的颜色仍可能保留。恢复 `status=無傷` 后，外框、角标、暗化恢复正常，失效格的 `X` 恢复为实心圆。翻面和负伤效果可以同时出现。

填写不合法的数字时，脚本会回退到内置默认值；新增加的武将如果没有内置默认值，相应数值会显示 `—`。把鼠标停在面板中的武将姓名上，可以查看不合法生诞年、统率或画像地址等资料的提示。建议仍按上表填写，避免面板回退后显示的数值与你的预期不同。

### 画像地址怎么填

把图片上传到 TTS 的 Cloud Manager 后，复制该图片的完整 URL，粘贴在 `image=` 后面。例如：

```text
image=https://你的图片完整直链
```

上面的示意地址不能直接使用，必须替换成你自己的真实图片地址。不要填电脑上的 `C:\...` 路径，也不要填图片所在网页的地址；需要能直接读取图片的 URL。不要给地址加引号。

模板中的 `image=` 特意留空。如果内置也没有画像，面板会显示 `画像未登録`；填入真实地址后会尝试加载你的画像。脚本会把完整 URL 直接写入 UI 的画像属性，同时登记自定义资源；不要把资源登记理解成直链画像已缓存或一定加载成功。这种写法支持 Steam Cloud 这类没有文件扩展名的直链。脚本会检查地址是否以 `http://` 或 `https://` 开头，但这并不能保证远端图片可访问；无法加载时，应检查地址内容和网络连接。

### 在主将右侧显示本隊陣旗

只需在该隊主将（`role=main`）的 Description 中新增一行，不必修改 Global 或副将资料：

```text
flag_image=https://你的陣旗图片完整直链
```

把示意地址换成上传到 TTS Cloud 的真实陣旗图片直链。字段也可以写成日本汉字 `陣旗=`，例如 `陣旗=https://你的陣旗图片完整直链`；两种写法选一种，不要重复填写。陣旗仍采用完整图片 URL，不使用本地 `C:\...` 路径或图片网页地址。按图像原比例显示，透明背景可以保留。

有旗时，`260 × 260` 主将画像与右侧 `90 × 240` 陣旗组成一组，间距 `20`，整组水平居中；旗与画像的纵向中心对齐。画像和上方「備大将」标题一起向左移 `55`，标题显示框宽 `266`，与画像对齐；下方姓名、年龄和能力行仍按整张主将卡居中。面板继续为 `600 × 1000`，高度不增加，两名副将画像和布局也不改变。

不显示时删除该行、留空 `flag_image=`，或填写 `flag_image=-`；陣旗隐藏后主将画像和「備大将」标题自动回到中央。字段别名 `陣旗=`、`陣旗=-` 同样适用。資料改好后可以点击「更新」或等待面板自动刷新。

陣旗保持原图颜色，不跟随浅手、深手或討死暗化，不加负伤角标，也不叠加「済」印；这些效果继续只作用于武将画像。陣旗自身没有悬停提示。

## 4. 修改资料、增加备队和关联普通部队

对于已经显示在面板中、且已建立索引的三名武将，面板约每 `0.75` 秒读取一次资料。修改姓名、统率、状态等资料后，可以等待自动刷新，也可以移开鼠标再指向令牌，或点击面板的 `更新`。画像读取还受网络和远端图片是否可访问影响。

定时资料刷新与背面贴花校验分开进行。令牌保持稳定时，定时刷新不会重新读取贴花和尺寸；如果非等比缩放令牌或手动增删／调整过贴花，重新悬停该令牌或点击「更新」，让脚本重新校验。

新建令牌或修改 `team`、`role` 后，如果没有正确识别，点击 `更新`，让脚本重新扫描桌上令牌并建立索引。

增加新的备队时，为三名武将设定一个未使用过的 `team` ID，例如 `new_sonae_01`，分别使用 `main`、`deputy1`、`deputy2`。在主将令牌填写 `formation`，三名武将各自填写姓名、生诞年、统率和画像。这样就能增加备队，无须把新名单写入 Global。

同一个 `team` 只能有一个 `main`、一个 `deputy1` 和一个 `deputy2`。复制令牌后要检查这些字段；同队同角色重复时，面板操作会提示，需要先纠正归属或角色。

普通部队现在推荐使用物件 **Tags** 关联隊伍，无须输入汉字或逐枚填写图片地址：

| 所属備隊 | 启用的英文标签 |
| --- | --- |
| 太田家 本陣 | `ota_honjin` |
| 太田家 岩付衆 | `iwatsuke_shu` |
| 太田家 江戸衆 | `edo_shu` |
| 太田家 松山衆 | `matsuyama_shu` |

右键物件进入 **Tags**，创建并启用对应标签；保留原有兵种标签。每枚棋子只启用一种所属标签，标签优先于 Description 的 `team`。自己增加的隊使用 `sg_team_` 加 `team` ID，例如 `team=new_sonae_01` 对应标签 `sg_team_new_sonae_01`。普通部队仅有所属标签时会作为部队识别，武将仍保留自己的角色和人物资料。标签的 TTS 原生创建权限、地图旗开关及排查步骤见[地图陣旗与英文标签](C:/Users/HP/Documents/ChatGPT/日本战国/TTS武将面板/地图陣旗与英文标签.md)。

旧的 Description 方式继续兼容。若不用所属标签，也可在普通部队 Description 中添加下面两行。保留原本已有的兵种资料，不要用这两行覆盖全部描述。

```text
team=iwatsuke_shu
role=unit
```

## 5. 面板的显示与操作
