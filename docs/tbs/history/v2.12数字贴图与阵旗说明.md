使用 `兵種与備隊面板合并版_日本漢字.lua`，完整替换 TTS 的 Global Lua，再点 **Save & Play**。不要把新版接在旧代码末尾。武将面板已经包含在合并版中。

## 这次已经改好

- 兵数、士気、移動均用透明 PNG 贴花，正背面各三枚。兵数 `1` 代表一百人；兵种标题和三项名称仍由底图提供。
- 0～7 共八张，思源宋体 JP Bold，256×256 透明底。共用字号和墨迹中心，不拉宽数字 1。
- 士気保留左键加、右键减；数字上没有额外提示文字。右键棋子也有 **士気＋／士気−**，修改当前朝上的一面。移動和兵数不可点击增减。
- 部队陣旗改为棋面内双面常显，位于数值栏左侧。所有玩家共同看见旗贴花；叠放武将时允许遮挡。
- 陣旗仍读取所属備隊主将 Description 的 `flag_image=`。部队归属标签不用改，武将面板的旗图也沿用同一地址。
- 数字、陣旗、敗走共用下面两项已经实测的参数。将领背面「済」保留 `BACK_STAMP_GAP = -0.099`。

```lua
UNIT_DEFEAT_FRONT_GAP = -0.01
UNIT_DEFEAT_BACK_GAP = -0.099
```

变量保留旧名称，实际已经统一控制三类部队贴花。数字没有单独需要调整的显示高度。

## 联机时只需上传八张

把 `数字贴图_v1/PNG` 里的八张 PNG 上传到你的云端图片空间。然后在 Global 顶部的 `UNIT_NUMBER_IMAGES` 表中，按数字分别替换引号内路径：

```lua
UNIT_NUMBER_IMAGES = {
    [0] = "这里填0的图片直链",
    [1] = "这里填1的图片直链",
    [2] = "这里填2的图片直链",
    [3] = "这里填3的图片直链",
    [4] = "这里填4的图片直链",
    [5] = "这里填5的图片直链",
    [6] = "这里填6的图片直链",
    [7] = "这里填7的图片直链"
}
```

这是填写位置示例；不要将这些占位文字覆盖当前已能访问的本机路径。替换后再 Save & Play。全军共用这八张图，无需给每个棋子添加图片地址。云端的陣旗、敗走和「済」地址已保留。

## 对齐与原有规则

按你现有的 1200×1200 底图计算：

| 内容 | 图片中心 X、Y | 图片占位 |
| --- | --- | --- |
| 兵数 | 1100、374.5 | 176×176 |
| 士気 | 1100、748 | 176×176 |
| 移動 | 1100、1081.5 | 176×176 |
| 陣旗 | 841、700 | 270×720 |

数字占位包含透明边距，实际字高约 132～138 底图像素。预览中的 `1／6／4` 是排版示例，不是初始化数值。

保留已有存档的正背面士気。新棋子及重置后仍从 0 开始；目前長柄足軽的正面上限 6、背面上限 5，移動为正面 4、背面 3。背面士気为 0 时，正背面显示敗走标记。这次只换显示方式，没有改这些规则。

数值更改时对比当前贴花，只在有变化时写回。不会删除旗图、「済」或你自行添加的其他贴花；部队旧版悬浮旗 UI 会自动清理。

若撤销某枚棋子的 `unit_*` 兵种标签，重新 Save & Play 会清理这套数字／敗走贴花及点击区；所属備隊的旗仍由其归属标签控制。士気数据保留，重新添加兵种标签后可以恢复。

若数字地址为空或格式无效，会移除那一位旧图片，避免继续显示错误数值；士気暂以原有文字后备，并在聊天日志中提示缺图。网络链接虽然格式正确但图片下载失败时，仍须检查直链或上传状态，脚本无法凭设置成功就判断图片已下载。
