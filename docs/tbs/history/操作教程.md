TTS 固定屏幕武将面板：从太田资正开始

完成后的效果：鼠标指向令旗，屏幕右侧出现武将原图、能力文字和当前命令。镜头移动时面板留在屏幕右侧。移开鼠标仍保留最近查看的武将；指向另一名登记过的武将时切换。按钮只记录已经生效的命令，不判断你的改令检定、命令延迟或指挥范围。

这个版本用于单人／房主。只需要粘贴一份《武将面板.lua》，XML 已经包含在脚本中。用户不需要安装 Python、Lua、Atom 或其他插件；“验证工具”目录是开发检查用的，不需要导入游戏。

1. **先准备测试存档**

先把现有战场手动另存为一个备份。首次使用请选 Global Lua 和 Global UI 都为空的桌面：可以是没有脚本的自制地图副本，也可以新开单人空桌。将测试存档取名为“武将面板测试”。

这份独立演示脚本定义了 onLoad、onObjectHover，并用 UI.setXml 生成整套 Global UI。如果正式存档已经有这些事件或已有 Global UI，不要直接覆盖；需要把事件和界面合并后才能安装。不要为了测试去清空原战场的自动化脚本。

2. **先做一枚临时令旗，外观暂时不限**

在测试桌面放一个筹码或棋子，也可以使用现有的太田资正武将算子。右键打开物件菜单，找到 Name／名称和 Description／描述。

名称填写：

```text
太田资正
```

描述填写：

```text
order=防御
```

order 用小写英文字母；等号是英文等号。命令可以是中文。复制上面两段最稳妥。名称必须与脚本配置区的键名一致；不要写成“太田資正”，也不要添加“本阵”等后缀。测试时只让这一枚地图标记使用这个名称，桌边资料卡可以另名“太田资正资料卡”。

以后令旗描述还可以有其他备注，脚本只更新 order= 这一行。

3. **此时先手动保存游戏**

打开 Games → Save & Load，在保存功能里保存当前测试桌。确认你刚放的令旗、名称和描述都已保存。

务必区分：保存游戏会保存桌面物件；脚本编辑器里的 Save & Play 主要保存脚本，然后重新加载存档，不会替你保存刚刚摆下的物件或改过的描述。

4. **打开脚本编辑器并粘贴脚本**

在顶部菜单找到 Scripting。部分界面可能把它放在 Modding 下；也可以右键任意物件 → Scripting → Lua Editor 打开编辑器，再切换到左侧 Global。

确认你当前选中的是：

```text
Global
Lua
```

不要选某个具体棋子的脚本，也不要在 UI／XML 页签里粘 Lua。

打开同目录下的《武将面板.lua》，全选、复制，粘进空白 Global Lua。第一次不要改任何内容，保持配置区的 image = ""。

点击 Save & Play。等待存档重新载入、聊天窗口出现“[武将面板] 已就绪”。

5. **先验证没有图片时的功能**

把鼠标先移到空处，再指向太田资正令旗。右侧应出现：

- 太田资正。
- 能力：5、数值：9(4)。这是按原图录入的演示文字，能力名称请按你的规则修改。
- 当前命令：防御。
- 进攻、防御、机动、重整四个按钮。
- 画像位置提示填写 Cloud URL；这一步故意没有图片，属于正常情况。

鼠标移到面板，点击“重整”。当前命令应变为重整。再右键令旗，描述里应变为 order=重整。

点面板右上角 × 可关闭。鼠标移出令旗再指回来，会重新打开。指向普通部队或空地时保留最后查看的武将，这是为了方便你移动鼠标去点按钮。

这一步通过后，手动保存游戏。

6. **上传太田资正原图并复制图片地址**

原图路径：

```text
C:\Users\HP\Desktop\战国资源\全球资源\战国乱武将\太田资正正面.png
```

在 TTS 顶部找到 Cloud Manager。不同版本菜单组织可能不同，官方旧文档写的是 Upload → Cloud Manager；你的界面也可能在 Modding 中。

打开 Cloud Manager 后：

1. 点击搜索框旁边的文件夹／上传图标。
2. 选择上面的太田资正图片。
3. 等待上传完成。
4. 单击已经上传的图片条目，复制该资源的 URL。
5. 可以先粘到记事本，确认是以 http:// 或 https:// 开头的完整图片资源地址。

这里是将图片上传到你的 Steam Cloud，不是发布创意工坊。请只上传这张图，不要使用 Upload All，以免把整个桌面的资源都重新上传。

如果你已经通过自定义物件导入把同一张图上传到了 Cloud，也可以复用该图片的现有 Cloud URL。Steam 的图片地址不一定以 .png 结尾，这并不代表地址有误。

教程主线使用 Cloud URL。本地 C:\ 路径、普通网页地址、图片搜索页或创意工坊页面地址，都不要填进这份脚本的 image 配置。

7. **把图片地址填入脚本**

再次打开 Global Lua。在最上方配置区找到：

```lua
image = "",
```

改成：

```lua
image = "这里粘贴刚复制的完整图片资源URL",
```

实际填写时，应当是一行 http:// 或 https:// 图片地址。保留两侧英文双引号和行末逗号。不要保留教程中的中文占位文字。

如果从上次存档之后移动过棋子或点过命令按钮，先退出编辑器并手动保存游戏，再返回编辑器改代码、按 Save & Play。这样不会丢失桌面改动。

重新加载后，等聊天窗口提示已就绪，鼠标移出再指回令旗。现在应能看到原有的完整太田资正武将图，包括半身像和图片里的数值。

8. **确认命令可以随存档保存**

在面板把命令设成“重整”，然后手动保存游戏。重新载入这个存档，再指向令旗，面板应读出“当前命令：重整”。

命令存在令旗的描述中；面板只是读写它。脚本不会自动读取另一枚独立命令筹，也不会自动实施你的改令规则。你应当在改令实际生效后再点按钮。

9. **把临时棋子换成小令旗**

功能确认后再制作小令旗。新令旗只要名称与配置区一致，描述里有 order=…，就能被识别，不需要重填 GUID。

如果保留旧令旗又复制新令旗，二者的 order=… 是独立的。正式使用时每名武将保留一个地图位置标记，避免同名物件的命令状态分叉。换物件时，把当前命令复制到新令旗，移走旧标记后再手动保存。

本脚本不自动绑定、搬运部队和令旗，也不自动计算指挥范围。它只解决屏幕显示与命令记录。

10. **扩展到第二名武将**

在 local LEADERS = { ... } 这个配置表内部追加一段。例如把整段表改成下面这种结构，并填写各自真实图片地址与能力：

```lua
local LEADERS = {
    ["太田资正"] = {
        name = "太田资正",
        stats = "能力：5    数值：9(4)",
        image = "太田资正的完整图片URL",
        asset = "sg_ota_sukemasa"
    },
    ["第二名武将"] = {
        name = "第二名武将",
        stats = "按你的规则填写能力",
        image = "第二名武将的完整图片URL",
        asset = "sg_leader_two"
    }
}
```

关键是第一段的结束括号后有逗号 `},`；每人的 asset 使用不同的英文字母／数字／下划线组合；桌面物件名称必须与方括号中的名称一致。每个令旗的描述分别记录自己的 order=…。

追加武将前先手动保存桌面，再 Save & Play。所有画像在脚本启动时登记，悬停时只切换，不会每次重新生成面板。

11. **调整位置与大小**

用 Ctrl+F 在 Global Lua 里搜索 sg_panel，找到面板外层定义。

- 右侧居中：rectAlignment="MiddleRight"，offsetXY="-20 0"。
- 左侧居中：改为 rectAlignment="MiddleLeft"，offsetXY="20 0"。
- 整体缩小：将 scale="1 1 1" 改成 scale="0.85 0.85 1"。
- 整体放大：可以试 scale="1.1 1.1 1"，注意自己的屏幕是否放得下。

第一次只调整 scale，不要只改外层 width／height，否则内部画像与按钮仍保持原位置。每次改后 Save & Play 查看实际结果。

12. **故障排查**

| 现象 | 检查内容 |
|---|---|
| 按 Save & Play 后令旗消失或改名撤销 | 之前没有手动保存桌面；重新摆好、命名、写描述，先保存游戏再运行脚本。 |
| 没有任何面板 | 确认粘在 Global 的 Lua 页；查看聊天窗口红色报错；本版本仅房主可见。 |
| 面板存在，但指向令旗不变 | 名称必须是太田资正；等“已就绪”后先移开鼠标再指回；资与資不是同一个字。 |
| 识别了武将但提示填写 URL | image 为空或不是 http(s) 地址。 |
| 图像空白／红色导入错误 | 检查完整图片资源URL、上传状态和网络；先将 image 改回空字符串，确认其余功能正常。 |
| 图片加载很慢 | 等待完成后重新悬停；30秒提示只是警告。可暂时清空URL测试其余功能。 |
| 当前命令显示未设置 | 令旗 Description 中没有 order=…；点任一命令按钮即可创建。 |
| 改了令旗描述但面板还是旧命令 | 把鼠标移出再指回令旗，触发重新读取。 |
| 命令读档后回到旧值 | 命令变更后要手动保存游戏；Save & Play 不代替游戏存档。 |
| 出现 `'end' expected near 'local'` | 这是 Lua 结构在前面被截断或少了 `end`、`)`、`}`；不要只补错误行，直接用本文件完整内容覆盖 Global Lua，然后只修改 `image = "...",` 这一行。 |
| Lua 报 unexpected symbol 或 unfinished string | 检查英文双引号、逗号、成对大括号；不要把 Markdown 的三反引号一起贴进去。 |
| 旧版脚本粘贴长图片地址后报 pattern too complex | 已在当前脚本修复。保留图片地址，把旧版 `local url = profile.image:match("^%s*(.-)%s*$")` 替换为 `local url = profile.image:gsub("^%s+", ""):gsub("%s+$", "")`。不必重新上传或缩短网址。 |
| 面板挡住右边地图 | 可关闭后按需悬停打开，或调小 scale／移到左侧。 |

已做的验证：使用本机 TTS 自带 MoonSharp Lua 引擎，对模拟 TTS API 的悬停、命令写入、房主过滤、删除物件、加载超时恢复等逻辑进行了检查，并检查 XML 结构与元素引用。尚未在实际 TTS 游戏画面里验证字体、资源下载和屏幕排版，需按上述步骤确认。开发检查不等于游戏内实测。
