# 敗走大图与叠放避让（v2.18.0）

当前使用用户提供的新直链，PNG为1200×800、RGBA。旧双面敗走贴花由升级清理，改为同一个Object.UI管理器中的两个图像根节点；正背共用一个预载资源，仅当前物理朝上的一面显示。它没有鼠标回调、点击区或实体碰撞体。

## 操作与规则边界

背面士气归零或原有手动敗走标志启用时出现，恢复士气或快捷补满解除敗走时隐藏。仍使用原来的`getDefeatText()`判定，不改变士气、行动、阵形、交戦、所属旗或存档格式。不新增自动撤退、敗走回合或RAN集结裁决；原有缺图文字后备保留。

## 调整参数

修改Global顶部`UNIT_ROUT_LAYOUT`，不用改数字、行动或陣旗的实测偏移。

| 参数 | 默认 | 含义 |
| --- | --- | --- |
| x / y | 500 / 700 | 1200棋面主体X0～1000、Y200～1200的中央 |
| width | 600 | 显示宽度；当前3∶2图片显示600×400 |
| max_height | 500 | 高图的高度上限，保持图片比例 |
| surface_clearance | 0.01 | 无武将时沿朝外方向离近面基准的间距 |
| commander_clearance | 0.02 | 叠放时离武将碰撞顶面的间距 |
| contact_tolerance | 0.08 | 允许的叠放接触误差；不是显示高度 |

后三项是部队物件局部单位，随其缩放。正面近面基准为碰撞体上表面；背面沿用已校准UI基准`surfaceBottom - back_ui_clearance`（`back_ui_clearance=-0.099`）。叠放检测本身使用真实碰撞体表面，不把渲染校准当作物理接触面。`UNIT_DEFEAT_IMAGE_ASPECT=1.5`对应本次图片宽高比；换图时同步修改。

## 识别与性能

- 面板已有的武将登记快照提供候选，角色须为`main`、`deputy1`、`deputy2`；沿用Description、所属Tags及已有姓名绑定规则。没有登记身份的任意画像不会触发避让。按实际位置遮挡检测，不要求武将与部队同队。
- 武将碰撞边界中心须位于部队棋面内，投影与标记区域相交，底部接近棋面或已接受的武将顶面。排除普通部队、旁边平放武将、悬空路过、正被拿起、正在加载及已移除的物件。
- 用世界碰撞包围盒八角转换到部队局部坐标，涵盖正背面、平面旋转、位置偏移及非均匀缩放。包围盒是保守估计；特殊不规则模型、斜立武将及厚度异常应单独实测。
- `setUnitRoutSnapshot()`只接收既有快照；面板原有0.75秒计时器调用`refreshUnitRoutOverlays()`。没有新增计时器、每帧扫描或`getAllObjects()`调用。没有敗走部队时直接返回。
- 有敗走时，候选武将边界每轮读取一次，再逐枚计算；界面属性未变不写入，位置更新不重建XML、不重新下载图片。识别更新通常不超过一个0.75秒刷新周期；实际帧率仍须实机测量。
- URL与其他已登记图片相同时复用已有资源名，避免正背面重复登记相同地址。保持原资源加载等待、最新状态回读及第三方UI/贴花保护。

实现参考官方[物件坐标与边界API](https://api.tabletopsimulator.com/object/#positiontolocal)和[UI位置、旋转、鼠标属性](https://api.tabletopsimulator.com/ui/attributes/)。同一UI中不同元素的覆盖顺序受XML次序影响，真实倾斜视角仍需验收。

## 实机验收

离线验证：Global4722项＋独立武将面板1168项＝5890项行为检查通过；XML、回调、事件、源码同步和发布字节一致检查通过。测试覆盖下述行为的模拟对象，但尚未代替实机视觉验收。

1. 全量替换Global，Save & Play；让一枚部队背面归零，确认中央新图、右栏及原图标正常。
2. 分别在正背面测试手动敗走，转动棋子、缩放镜头、倾斜视角，确认仅当前面有图。
3. 叠放已登记武将，确认标记越过顶面；拿起、移开、入袋、销毁武将后恢复近面。相邻武将和空中拖动不应触发。
4. 点击士气及行动等区域，确认大图不拦截；快捷补满后立即消失，存档重载保持状态。
5. 在实际最大规模战场、多人环境观察帧率。离线模拟不能证明GPU层序、网络加载、遮挡高度或多人性能。
