# 状态图标 v1 · 交戦、指揮外与阵形

本目录提供四个状态图标，尚未接入 TTS Global Lua。交戦与指揮外为**暗朱红实心圆章、圆外透明**：

- **交戦 / `engaged`**：象牙色交叉太刀。沿用用户选定的红色版本，三份图标导出和既有定位均保持 revision 4 原样。
- **指揮外 / `out_of_command`**：根据用户上传的实物军配照片从零绘制。黑漆扇面两侧内凹收腰、上下角圆弧，采用古朴的哑光旧木质感和暗金土色包边，去除光泽与反光；中央黑木脊贯穿扇面并延成长柄，柄帽同样压暗。军配倾斜约 25°，去除参考照片中的全部文字，中央斜杠改为黑色，暗朱红圆章与构图不变。

两者都按 **100 × 100** 显示，分别位于标题栏左右两侧，**可以同时出现，不能作为互斥状态复用一个位置**。

指揮外的当前效果以独立图标为准：[指揮外 512 PNG](./out_of_command.png) · [100 PNG](./out_of_command-100.png) · [1024 源图](./源图/out_of_command-1024.png) · [manifest.json](./manifest.json)。按用户要求，本轮不生成总览、棋面或其他预览图。

留白按 alpha > 0 的像素外接矩形测量，包含低透明度抗锯齿边缘。100 px 版本的抗锯齿像素延伸到画布边界，主体圆边仍留约 1 px 余量，四角透明。圆章内部为实心底色，圆外透明；图标不依赖文字。建议保持原有颜色，不对整张图片乘黑色或降低透明度。

## 阵形 · 密集与散開（revision 9）

新增两枚**浅米旧纸底、深褐边、黑色阵笠**的横向图标，不使用暗朱红。每图恰好六个同尺度的俯视阵笠兵位：密集为紧靠的两行三列，散開为疏开、错列的两行三列；两图兵位大小一致。

| --- | --- | --- | --- |

纸牌主体略扁，以透明上下留白适配 2:1 画布，**并非纸牌本体填满 240 × 120**。两图按 alpha > 0 测得的左／上／右／下留白相同：512 × 256 版为 `3 / 32 / 3 / 32 px`，240 × 120 版为 `0 / 14 / 0 / 14 px`，1024 × 512 版为 `10 / 69 / 10 / 69 px`。具体轮廓与哈希见 manifest。

建议按整张画布 **240 × 120** 显示，候选左上角 **`(734,1042)`**、中心 **`(854,1102)`**，位于大方框右下、数值栏左侧；画布与右分隔线、底框均留 24 px。密集与散開**共用这一位置，互相切换**。定位仅核对了框线和一张既有槍足軽成品，尚未完成全兵种遮挡检查或 TTS 实机验收。不要裁掉透明留白后重新定位。本轮未生成阵形预览或新总览。

## 代码侧交接

- 本次为 **`revision: 9`**，新增 `formation_close` 与 `formation_open`，按上节的同一候选位置互斥切换；既有 `engaged`、`out_of_command` 的 manifest 资产条目、PNG 与定位保持不变。交戦沿用 revision 4，指揮外沿用 revision 8；本轮不更新预览，当前效果以各独立图标为准。
- 固定标识为 `engaged`、`out_of_command`、`formation_close`、`formation_open`。前两者独立控制且允许同时显示，不能复用同一坐标；后两者共用阵形位置，互相切换。
- 四个 `cloud_url` 均为空。仓库预览链接不代表已配置或已验证的 TTS 图片资源；需要代码侧选定图片托管、登记资源并验证加载。
- 本稿仅交接图片、尺寸和定位。状态如何触发、保存／恢复及清除由代码侧按已确认规则处理；这里不推测交战或指挥范围的自动判定、回合重置等逻辑。
- 1200 棋面像素坐标需映射到实际物件坐标／UI。已有正背面渲染方式、厚度偏移及资源登记顺序请按代码侧交接保留，不能直接把本文件的像素数当作 TTS 世界坐标。
- 实机检查应覆盖正反面、多人、缩放、倾斜和移动后的透明排序，检查单状态与双状态同时显示，并确认图标不拦截既有操作区域。
- 其余三个标识 `fire_ready`、`fire_loading`、`routed` 尚未制作，没有导出占位图。
